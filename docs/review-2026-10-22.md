## 按项修复

### R1 · 语言绑定：统一语言目录（P1）

- `workflow.ts` `editorLanguageBinding`：删除写死的 9 语言"其他语言"清单，改为遍历共享
  目录 `SUBTITLE_LABEL_TO_CODE` 识别外语证据（pt/it/ru/… 不再漏判为 `unknown`）。
  标题为 `Português` 的编辑器 + 目标语 `ja` → `mismatch`，`classifyTranslatePhase`
  不再误判 `READY`。
- 编辑器 code 属性比对改用 `languageCodeMatches`（base↔variant 兼容，见 R2）。
- 落实报告建议"发布前再次检查语言绑定"：`autoTranslateAndPublish` 在 READY 之后、
  发布之前**重新派生** `actionDomForLanguage`（同时重检绑定并修复编辑器宿主替换后的
  作用域失配风险）。

### R2 · 语言标签：保留简繁/地区变体（P1）

- `workflow.ts` `languageCodeFromElement`：不再无差别剥掉末尾括号（旧逻辑把
  `中文（简体）`→`中文`、`葡萄牙语（巴西）`→`葡萄牙语`），只剥 fixture 的 `(pending)`；
  状态标注交给共享解析器处理。
- `schema.ts` `resolveLanguageCodeFromLabel` 重写：
  1) 完整标签精确匹配（目录已含 `中文（简体）`/`中文（繁体）`/`葡萄牙语（巴西）` 等）；
  2) 仅剥**状态标注**（`（视频语言）`/`(Video language)`/`（草稿）`/`(draft)`/`（已发布）`/
     `(pending)`）；
  3) 无括号状态文本（`韩语 草稿`、`韩语 已发布2026年10月21日`）走最长前缀 + **空白边界**
     —— 括号不再视为可丢弃后缀，`英语（美国）` 不会折叠成 `en`。
- 新增地区条目：`英语（美国）`→`en-US`、`英语（英国）`→`en-GB`（保留地区身份）。
- 新增 `languageCodeMatches(a, b)`：相等或 base↔variant（`en`↔`en-US`、`pt`↔`pt-BR`、
  `zh`↔`zh-Hans`）视为同一语言；`zh-Hans` vs `zh-Hant`、`en-US` vs `en-GB` 不等价。
  workflow 的行定位/跳过/选项目标比对全部改用它（行解析保留变体后 `en` 目标仍能命中
  `英语（美国）` 行）。

### R3 · unique 歧义终止定位（P1）

- `dom-service.ts` `constrainCandidates` 返回三分结果（found / missing / ambiguous）。
- `resolveDomTarget`：`unique` 目标在**任一分支**出现多候选 → 立即返回 `null` 终止，
  不再落到更低优先级选择器"挑一个"。两个启用的 Publish 按钮（其一带
  `id=publish-button`）→ 拒绝；`.specific` 多候选 → 不再逃逸到 `#generic`。

### R4 · Hub 缩写播放量保留倍率（P1）

- `metrics.ts` `parseDisplayMetric` 补齐中文倍率：`万`×10⁴、`亿`×10⁸、`万亿`×10¹²
  （`1.2万` → 12000，不再是 1.2）。
- `content-adapter.ts` `readCardViews` 的 aria-label 与 metadata-span 路径统一走
  `parseDisplayMetric`（`1.2K`→1200、`1.2万`→12000，`viewsRounded` 如实标注）。

### R5 · 控件缺失 ≠ 合法无值（P2）

- `collector.ts` 读数状态扩为五态语义：`VALUE` / `ABSENT`（占位符）/
  `MISSING`（DOM 无此控件）/ 空白-present / `UNREADABLE`。新增
  `readMetricEventually` 返回 `{text, present}`；`applyMetric` 增加 `controlPresent`。
- **MISSING 不进 `absentFields`** → `missingCore` 触发 PARTIAL，并记
  `METRIC_CONTROL_MISSING` 警告（信息性，不入 lossCodes：跨页健康恢复仍 COMPLETE）。
- **语义合成（与 H5 的真实 DOM 校准一致）**：任一咨询页显示显式占位符（`—`/`N/A`…）
  即为"UI 自己声明无值"（合法缺失，COMPLETE）；两页都既无控件又无占位符才是无解释
  缺失（PARTIAL）。控件存在但空白沿用 2026-09-07 真机语义（`.subscribers-trend` 空节点
  即无值显示）→ 合法缺失。

**探针构造修正（重要）**：审查副本的 R5 探针只 `remove()` 已挂载节点，但
`mountStudioFixture` 在导航时**重绘** ANALYTICS 页——被删的 `analytics.subscriberDelta`
带着 `+120` 复活，实际采集到完整 `{views:12345, subscriberDelta:120}`，COMPLETE 是
事实正确的（本机 scratch 运行实证）。探针自身声明的场景是"两个 subscriber 控件都缺失"，
已改为用 fixture 选项**全程不挂载**这两个控件（断言不变），并补一条对照测试
"Dashboard 控件缺失但 Analytics 恢复 → 仍 COMPLETE（含 `METRIC_CONTROL_MISSING`）"。

### R6 · 活动容器决定内容家族（P2）

### R7 · 发布等待并入统一翻译预算（P2）

- `workflow.ts` `autoTranslateAndPublish`：删除独立的 8 秒发布前置等待（其超时会在

  `captionsReadyTimeoutMs ?? 90s` 同一预算："控件存在"与"可提交"分开检测，两者都
  满足才点击。发布按钮在翻译期间禁用、9 秒后启用 → 任务正常 COMPLETED（探针覆盖）。
